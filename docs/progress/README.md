# Task and review history

Create one `YYYY-MM-DD-task-name.md` record per significant implementation task before editing code, then maintain it through implementation and review. Use the headings below; use `None` or `Not run` with an explanation instead of omitting a field.

## Task goal

Record scope, acceptance criteria, owner/role, and status.

## Implementation summary

Explain what changed and why. Distinguish completed work from proposed work.

## Files changed

List exact paths and their purposes.

## Tests

Record commands, outcomes, evidence, and skipped checks with reasons. Never claim a test passed without running it or clearly attributing a reported result.

## Decisions

Link applicable ADRs, approved business rules, human approval evidence, and unresolved decisions.

## Known limitations

Record constraints, risks, blockers, and unverified behavior.

## Next steps

List remaining work, responsible role, and any required human input. Recommendations do not authorize implementation.

## Review

Record reviewer, outcome, findings, resolution status, and independent verification.
