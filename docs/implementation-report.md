## Components

HomeExperience composes Navigation, Hero, RouteSearch, TrustSignals, HowItWorks, MarketplacePanels, UpcomingTrips, MatchingPreview, SafetySection, ClosingCta, Footer, and PreviewDialog. Reusable primitives include BrandLogo, TravelerIdentity, TripCard, Button, SectionHeading, and LanguageProvider.

The App Router layout provides metadata and self-hosted Inter. The homepage is prerendered, with a client boundary for language, form, menu, and dialog state. Data and copy are separated from components. There is no Vite configuration, prototype page switcher, or fake API.

## Visual comparison and remaining differences

Reviewed Chrome screenshots against the structured Make homepage source. The desktop retains the source's section order, large left-aligned headline, 768px search card, 1200px content width, trust row, three process cards, black/orange marketplace panels, four trip cards, three match rows, safety grid, closing CTA, and dark footer. The logo uses the exact source vector paths.

Intentional differences:

- Mobile/tablet use a collapsible navigation menu; the smallest screens omit the header account CTA and stack dense content.
- Form labels are associated with inputs; controls remain aligned when labels wrap. Native selects retain their arrows.
- Muted text uses `#757575` instead of the source's `#a0a0a0` on light surfaces; dark-surface secondary copy retains the source treatment.
- Sample-data labels clarify that trips and scores are illustrative. The summary route is consistent with the search, rather than reversed as in the prototype.
- Future-screen actions open local informational dialogs or scroll to sections.
- Mobile spacing and typography are adjusted for readability; safety cards stack at narrow widths.
- Flags/emoji render according to the OS; this Windows Chrome renders country flags as letter codes. Chinese uses the system's CJK font fallback because Inter has no CJK glyphs. Dates follow native browser formatting.

The MCP returned structured source and asset links, not a rendered Make homepage screenshot. This is a source-based visual comparison, not a claimed pixel-perfect screenshot diff. Safari and Firefox were not tested.

Evidence is in `artifacts/browser-results.json` and the desktop/tablet/mobile screenshots, including language variants and the trip dialog.
